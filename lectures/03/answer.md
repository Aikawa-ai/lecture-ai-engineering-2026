# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  質問「AIE2026の講座の宿題にある3レベルとは何ですか？」
  第1回の `app.ask`：講座のことを知らないので、「レベル1：基礎／レベル2：応用／レベル3：発展・実践」という一般論で答え、「お手元の資料を確認してください」で終わった。「どれか1つ」は「講座によってはある」という一般論として触れただけで、この講座の決まりとしては答えていない。
  第3回の `app.agent`：「基礎（講義内容の確認）・実装（自分でコードを書く）・発展（調査や試行）」の3つで、どれか1つに取り組めば完了、原則として採点しない、と答え、最後に「関係する回：第1回」を付けた。`data/glossary.json` の `homework-levels` の定義と合っている。
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  「LoRAとQLoRAの違いは？」では `search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回。docstring に「query には調べたい用語を1つだけ入れる」とあるので、用語ごとに分けて検索していた。
  「第2回の内容から確認問題を1問出して」では `make_quiz({'lecture': 2})` の1回。PEFT の問題が返り、モデルは答えを伏せて「答えが分かったら教えてください」と出題した。
- 1つの質問での LLM 呼び出し回数（`requests`）：
  LoRAとQLoRAの質問：`requests=2, tool_calls=2`（入力 1196 トークン、出力 196 トークン）。2回の検索は1回目の応答でまとめて呼ばれ、結果を受け取った2回目の呼び出しで回答した。
  確認問題の質問：`requests=2, tool_calls=1`
- 追加したツールと、docstring に書いた説明：
  `make_quiz(lecture: int) -> str`：指定した回の用語を `load_glossary()` から集めて `random.choice` で1つ選び、`{"lecture", "question": "「○○」の意味は？", "answer": 定義}` を JSON で返す。用語のない回（第0回など）には「第0回の用語は用語集にありません。用語がある回: 1, 2, 3, 4, 6」と返す。
  docstring：「指定した回（1始まりの整数）の用語から1つを選び、確認問題と答えを返す。『第2回の確認問題を出して』『第3回の復習クイズがほしい』のように、復習用の問題を求められたときに使う。返り値の answer は、利用者が答えてから示す。」
  `--list-tools` で3つ目のツールとして表示され、`uv run pytest -q` は 15 passed

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  同じ2つの質問（Q1「LoRAとQLoRAの違いは？」、Q2「AIE2026の講座の宿題にある「3レベル」とは何ですか？」）を、条件ごとに `--trace` 付きで2回ずつ実行して比べた。モデルは `gemini-3.5-flash-lite`
  条件0（基準）：元のまま
  条件A：`search_glossary` の docstring の「query には調べたい用語を1つだけ入れる（例: "LoRA"）」を「調べたい用語が複数あるときは、query にまとめて入れて1回で検索する（例: "LoRA QLoRA"）」に変えた。
  条件B：`INSTRUCTIONS` から「用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する。」の行を消した。
  条件C：条件Bに加えて、docstring の「AIエンジニアリングの用語や、この講座（AIE2026）に固有の言葉について答える前に使うこと。」も消した。
  1つの条件を試したら元に戻してから、次の条件を試した。
- 結果：
  どの条件も、2回の実行でツールの呼ばれ方と回数は同じだった。
  条件A：Q1 の検索が2回から1回にまとまった。`search_glossary("LoRA QLoRA")` を単体で呼ぶと LoRA と QLoRA の両方が返るので、答えに必要な情報は足りていた。tool_calls は 2→1 になったが、requests は 2 のままだった（ツールは1回目の応答でまとめて呼ばれるので、2回に分けても LLM の呼び出し回数は増えていなかった）。「Low-Rank Adaptation」「Quantized LoRA」のような正式名称は、ツールの結果には入っていないが、条件Aの2回、条件Bの1回、条件Cの2回の回答に出た。モデルが元から知っていたことで補ったのだと思う。
  条件B・C：検索の行を消しても、docstring の文も消しても、Q1・Q2 とも答える前に検索した。回答の内容も基準とほぼ同じで、最後に関係する回（第2回・第1回）が付いていた。
- 気づき・疑問：
  docstring の書き方1つで、ツールに渡す引数の形と呼ぶ回数が、2回とも同じように変わった。モデルはツールの説明文を使い方の指示として読んでいる。
  用語をまとめて検索できたのは、`search_glossary` が名前が検索語の中に含まれるものも拾うから。検索結果は最大3件（`MAX_RESULTS = 3`）なので、`"LoRA QLoRA PEFT 量子化"` のように4つ入れると PEFT・LoRA・QLoRA の3件しか返らなかった。まとめる指示は、ツールの実装と合わせて考える必要がある。
  LoRAのようにモデルが元から知っている用語でも検索したので、今回のモデルでは、指示を減らしても調べずに答える方向には崩れにくかった。
